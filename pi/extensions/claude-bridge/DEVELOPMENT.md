# pi-claude-bridge development

For maintainers and embedding hosts. What the bridge does for a Pi user is [README.md](README.md); the mechanics live as doc comments on the modules named below, and this file holds the invariants that span them and the contracts a host relies on.

## Invariants

- `src/models.ts::buildModels` maintains an explicit supported-model list and projects Pi metadata; it does not synchronize from SDK picker snapshots. Anthropic's [model configuration](https://code.claude.com/docs/en/model-config#work-with-fable) documents that Fable picker entries depend on organization availability and explicit selection can succeed without an entry. Fable metadata and effort support follow the [migration guide](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide). `tests/unit-models.mjs` checks projection and metadata; `tests/unit-provider-stream.mjs` checks the model requested by Pi reaches SDK query options.
- Request-owned state lives in a lane, never in a module-level binding. Pi calls one provider instance concurrently for parents, subagents and sibling conversations, so `src/request-lane.ts::runInRequestLane` keys an `AsyncLocalStorage` lane by `SimpleStreamOptions.sessionId`, and the active query context, Pi stream, pushed-context stack, watchdog, billing identity and Claude session record resolve through it. A fresh request clears its lane's billing identity before credential validation, so a logged-out request cannot leave the previous email visible. A billing probe also carries an attempt token, so an older probe cannot overwrite a newer result in the same lane. A callback registered on a host-owned emitter (an `AbortSignal` listener) runs in the caller's context and must re-enter its lane explicitly. Presence is judged against `undefined`: an empty string is a named lane. The lane carrier and the per-session registries sit on `globalThis` under versioned symbols, because a parent and a child can load separate copies of the module. `tests/unit-session-lanes.mjs`, `tests/unit-foreign-conversation.mjs`, `tests/unit-billing-identity.mjs`.
- `session_shutdown` removes only the query, Claude-session and billing-identity lanes recorded for that `SessionManager` at its `session_start`, since an in-memory session forks by mutating the same manager's id. The billing-identity publisher remains process-global for surviving siblings and reload handoff. A request with `cacheRetention: "none"` (Pi's compaction and branch-summary one-shots, fresh `sessionId` each, no shutdown ever) releases its lane when it settles. `src/index.ts` around `ephemeralLane`.
- A tool-use turn ends at the stream's `message_stop`, because `message_delta` is what carries the real output-token count and the SDK invokes MCP handlers before it arrives. The early signals only arm the grace timer in `src/assistant-stream.ts::scheduleToolUseTurnEnd`, which force-finalizes a turn whose terminal events never come.
- A tool result whose id was never registered in the active turn is refused, never queued against another call; the remaining handlers get an internal-error result so the turn cannot report success. A queued result whose handler has not fired by the next child message boundary is parked, still consumable, because the SDK staggers handler invocation. A query torn down with results outstanding writes diagnostics, marks the session for rebuild, and re-imports delivered results from Pi history next turn. `src/query-state.ts`, `tests/unit-tool-drain.mjs`, `tests/unit-queue.mjs`.
- An unpaired `tool_use` in a rebuilt session is paired with an explicit `is_error` result saying the output was lost, never a bare placeholder a model reads as output. `src/tool-pairing-audit.ts`.
- `src/transcript.ts::conversationMessages` defines the index space: every cursor, prompt window, deferred-replay plan and fingerprint counts `user`, `assistant` and `toolResult` messages, on the provider side and on the `buildSessionContext()` side alike. The system prompt and the tool set are read with `getCurrentSystemPrompt` and `getCurrentTools` over the full transcript, and a rebuild imports no system message. `tests/unit-transcript.mjs`, `tests/unit-transcript-context.mjs`, `tests/unit-transcript-persistence.mjs`.
- The provider is registered natively and unconditionally, once, by the primary module instance: `src/native-provider.ts::buildNativeProvider` through `pi.registerProvider`, with `auth.apiKey.check` and `resolve` answering from the existence-only credential probes in `src/auth-presence.ts`, so Pi hides the models while no account is connected. Pi's registration is upsert-by-id and replaces the stored object, so `PRIMARY_INSTANCE_KEY` and `ACTIVE_STREAM_SIMPLE_KEY` in `src/index.ts` keep a reloaded child module from swapping in its own `streamSimple` closure. A host below the peer floor gets `NATIVE_PROVIDER_UNSUPPORTED_MESSAGE` once instead of a wrong registration. Both native entry points route through the Claude Code subprocess; there is no raw API path, which is what keeps billing on the subscription.
- The stream-idle watchdog monitors only silence before the first output (`src/stream-idle-watchdog.ts::shouldMonitor`). After output starts, long gaps are legitimate: tool execution or extended thinking can pause streamed deltas. A child that dies mid-message throws from the generator and is surfaced that way.
- Diagnostic logs are written only with `CLAUDE_BRIDGE_DEBUG=1`; normal Claude session files and Pi session markers are independent of debug mode. No diagnostic line carries a tool payload or user-authored message content. `src/debug.ts`, `tests/unit-debug-discipline.mjs`.

## Pi-owned tools

`src/tool-isolation.ts` hides Claude Code built-ins with `tools: []` and a denylist that includes MCP-resource discovery. `allowedTools` auto-approves permissions; it is not a visibility boundary. Every SDK query has `strictMcpConfig: true`, only the Pi bridge MCP server, cloud MCP disabled in its environment and a fail-closed `PreToolUse` hook. Only nonempty `mcp__custom-tools__<name>` names may pass; malformed input, throwing getters, foreign namespaces and future built-ins are denied. Deferred-input continuations copy the full query-option policy. With prompt appending disabled, `settingSourcesForQuery` defaults to `["user", "project"]` but never relaxes MCP isolation.

Pi advertises tools from the current transcript manifest through `src/index.ts::resolveMcpTools`. `src/tool-mapping.ts::isPiDispatchable` requires manifest membership, even for bare names. Explicit Pi custom-name mappings win; a genuine Pi tool resembling a cloud connector is still a Pi tool under the bridge prefix. An unexpected child-side call is suppressed on streamed, assistant-boundary and fallback paths, never handed to Pi. Its query-scoped `childSideCalls` entry prevents compaction from rebuilding a history missing that execution. It carries no result payload. `tests/unit-tool-isolation.mjs`, `tests/unit-child-executed-tools.mjs`, `tests/unit-compact-restart.mjs`.

## Config channels

`src/config.ts::loadConfig` layers built-in defaults, `<piUserDir>/claude-bridge.json`, then a trusted project's `.pi/claude-bridge.json`. In isolated mode it reads only the user file. Only explicit nested `provider.*` and `promptContext.*` fields are decoded; manager `settings.json`, flat keys and removed options cannot alter the result. Effort is normalized after layering, so an invalid higher value clears a valid lower one. `recordProjectTrust` requires `isProjectTrusted?.() === true` before any project configuration is read.

## Embedding hosts

- `CLAUDE_BRIDGE_ISOLATED=1` (`src/config.ts::isolatedFromEnv`) suppresses cwd-ancestor AGENTS, project configuration and project `APPEND_SYSTEM.md` discovery, plus the `PATH` executable search. Settings come only from `<piUserDir>/claude-bridge.json`; logs still resolve under `PI_CODING_AGENT_DIR`. `tests/unit-isolation.mjs`.
- Startup preflight (`src/claude-executable.ts::preflightClaudeExecutable`) preserves `code`, `errno`, `syscall`, `path`, `cwd` and the detected executable file type on the error it hands the SDK.

## Session persistence

Ordinary queries use the process's Claude credentials and `CLAUDE_CONFIG_DIR` for both child environment and `cc-session-io` session files. A persisted marker with the old `accountProfileId` field is rejected at restore, even if its UUID exists in the ambient account directory; Pi history is imported into a fresh session instead. Ordinary markers still use their Pi session id, cwd and fingerprint guards. A killed child cannot race its orphaned JSONL writer into a replacement because `forceRotate` creates a new session id. `tests/unit-session-marker.mjs`, `tests/unit-transcript-persistence.mjs`, `tests/unit-compact-restart.mjs`.

## Rate limits

`src/rate-limit.ts::normalizeRateLimitUtilization` reads a value in `(0, 1]` as a fraction and `(1, 100]` as a percent; exactly `1` is ambiguous and resolves to full, the fail-closed direction. `formatAllowedRateLimitWarning` emits a neutral toast from `ALLOWED_RATE_LIMIT_WARNING_UTILIZATION_THRESHOLD` up and never quotes a `% used` figure. Rate-limit errors are deduplicated before notification and emitted as `kendex:rate-limit` for `pi-qol`.

## Tests

```bash
npm run typecheck       # TypeScript without emitting files
npm test                # offline tests/unit-*.mjs
npm run test:int        # live tests; requires approval and Claude credentials
```

The integration suites (`tests/int-*.sh`, `tests/int-*.mjs`) need the `pi` CLI, a logged-in Claude Code and optional alternate-model settings. `npm test` does not run them. A test that spawns a child pins `HOME`, `PI_CODING_AGENT_DIR` and `CLAUDE_CONFIG_DIR` explicitly, because a spawned child inherits the process's start environment rather than a harness override.
